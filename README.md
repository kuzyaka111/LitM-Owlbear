# Легенда в Тумане — расширение Owlbear Rodeo

Версия 0.1.0. Первый технический прототип по утверждённому оформлению.

## Что уже реализовано

- Основная кнопка «Лист персонажа» в области расширений Owlbear.
- Отдельная кнопка «Панель ведущего» в панели инструментов сцены.
- Кнопка ведущего регистрируется только для GM при открытой сцене, дополнительно имеет фильтр роли. Нажатие проверяет роль ещё раз и открывает отдельное модальное окно. Выбранный инструмент карты при этом не переключается.
- При смене роли или закрытии сцены кнопка ведущего удаляется. Страница ведущего проверяет роль до отображения её содержимого.
- Четыре демонстрационные темы, выбор тегов, отметки развития, рюкзак, редактируемое имя и заметки.
- Панель ведущего с демонстрационными тегами сцены и локальными заметками.
- Адаптивная компоновка и учёт настройки уменьшения анимаций.
- Тестовые изменения сохраняются в localStorage отдельно для комнаты, пользователя и типа окна.

## Границы версии

Это проверка интерфейса и точек входа. Здесь ещё нет Supabase, общего состояния между игроками, назначения персонажей, полноценного редактора тем, автоматизации правил или бросков. Представленный герой и сцена — авторские демонстрационные данные, а не официальный готовый персонаж.

Сохранение в браузере не является резервной копией и не переносится на другой компьютер. В приватном режиме или при блокировке хранилища браузером оно может быть недоступно; интерфейс сообщает об ошибке. Заметки ведущего не передаются в общие метаданные Owlbear.

Проверки интерфейса по роли не заменят серверные права доступа будущей базы данных. При подключении Supabase необходимо отдельно реализовать проверку участия в кампании и права на записи. URL страницы ведущего не является секретом. Вне Owlbear она показывает только локальный демонстрационный режим.

## Состав

- `src/` — интерфейс и логика интеграции.
- `public/manifest.json` — установка расширения.
- `docs/` — готовые файлы для GitHub Pages, без необходимости собирать их у себя.
- `dist/` — результат сборки.
- `tests/` — проверки ролей, окон, путей, локального сохранения и действий интерфейса.
- `package-lock.json` — зафиксированные зависимости.

## Публикация на GitHub Pages

1. Создать отдельный публичный репозиторий, `LitM-Owlbear`, с начальным README.
2. Разместить в нём содержимое этого проекта. Для установки достаточно готовой папки `docs/`, но исходники также стоит сохранить.
3. В репозитории открыть Settings → Pages. Выбрать Deploy from a branch, ветку `main` и папку `/docs`.
4. Дождаться успешной публикации. Убедиться, что по опубликованному адресу доступны `manifest.json`, `index.html`, `gm.html` и `background.html`.
5. В профиле Owlbear нажать Add Extension и вставить адрес вида `https://kuzyaka111.github.io/LitM-Owlbear/manifest.json`.
6. Включить расширение в тестовой комнате.

Пути внутри пакета относительные: он рассчитан и на корень сайта, и на подпапку GitHub Pages. Домен покупать не требуется.

## Проверка в настоящей комнате

Эта проверка пока НЕ проведена. После публикации нужно открыть комнату ведущим и вторым участником:

1. В обоих окнах есть кнопка листа в области расширений.
2. Без открытой сцены лист работает, кнопки ведущего в инструментах нет.
3. С открытой сценой у ведущего появляется кнопка панели; у игрока она отсутствует.
4. Нажатие открывает отдельную панель ведущего, а выбранный инструмент карты не меняется.
5. Закрытие сцены и изменение роли корректно убирают кнопку/панель.
6. После закрытия и повторного открытия листа сохраняются имя, заметки, рюкзак и отметки на том же устройстве.
7. На телефоне лист перестраивается в одну колонку, элементы не выходят за ширину окна.

Не использовать эту версию как единственное хранилище реальной кампании.

## Разработка

Нужен Node.js, совместимый с Vite 8 (например Node 24).

```sh
npm ci
npm test
npm run dev
```

Сборка:

```sh
npm run build
```

После изменений скопировать содержимое `dist/` в `docs/`, включая `.nojekyll`, и опубликовать обновление. Секретные ключи не нужны для этой версии; добавлять их в репозиторий нельзя.
