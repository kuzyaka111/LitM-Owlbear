# Лист и панель ведущего в отдельной вкладке

В настройках листа есть кнопка «Открыть в отдельной вкладке». В панели ведущего та же кнопка обозначена ↗ около облака. Окно в комнате закрывается, а связанные данные и интерфейс открываются в новой вкладке браузера. Повторное нажатие переключает на уже открытую вкладку этого типа. Лист и панель ведущего можно открыть отдельно одновременно.

В отдельной вкладке работают редактирование, выбор персонажа, отметки и зачёркивание, заметки, Подсчёт силы, броски, общие данные Братства, облако, просмотр и назначение персонажей ведущим. Кнопки размещения данных панели ведущего на поле сохраняются. Для выбора изображения открывается библиотека в исходной комнате; после выбора фокус возвращается к панели.

Перенос карточек на поле перетаскиванием в этом режиме отключён. Перестановка карточек внутри листа остаётся доступна. Уже вынесенные карточки продолжают синхронизироваться, доступны прежние кнопки возврата.

Верхняя полоса показывает связь с комнатой и содержит «Вернуть в Owlbear». Эта кнопка дожидается сохранения, открывает прежнее окно в комнате и закрывает отдельную вкладку. Простое закрытие отдельной вкладки сохраняет записи; при следующем открытии они загружаются из того же хранилища комнаты. Обновление отдельной вкладки повторно подключается к комнате.

## Условия работы

- Комната Owlbear должна оставаться открытой. При её закрытии или обновлении соединение прекращается: нужно открыть отдельную вкладку заново из комнаты. Вкладка не превращается в независимый офлайн-лист.
- Игрок открывает свой лист, а панель ведущего доступна только GM. При снятии роли ведущего открытая отдельная панель закрывает доступ к содержимому и действиям.
- Если браузер блокирует новую вкладку, разрешите всплывающие окна для комнаты Owlbear и повторите нажатие. Существующий лист в этом случае остаётся открыт.
- Браузер сам определяет, откроется вкладка или отдельное окно. При желании вкладку можно перетащить в другое окно браузера.

## Сохранение и безопасность

Вкладка подключается к фоновой странице той же комнаты через закрытый MessagePort. Проверяются точный источник окна, origin и случайный идентификатор открытия; адрес страницы сам по себе не даёт доступа к данным. Роль берётся из Owlbear, а идентификаторы комнаты и игрока — из фонового контекста.

Из-за разделения браузерных хранилищ между встроенными страницами и обычными вкладками записи не читаются из независимой копии localStorage. Используется зеркало разрешённых ключей с записью обратно в хранилище комнаты. Листу доступны только собственный лист и его резервная копия; частные данные ведущего и ключ облачной сессии ему не передаются. У панели GM остаётся та же облачная сессия.

Несохранённая в комнате запись временно остаётся в черновике браузера отдельной вкладки. При повторном подключении черновик не заменяет данные автоматически: предлагается явное восстановление. При наличии ожидающих записей браузер получает предупреждение о закрытии. До завершения отправки не очищайте данные браузера.

Адаптер использует сериализуемые сообщения закреплённого Owlbear SDK **3.1.0**. Функции обновления SDK превращает в частичные изменения до передачи; удалённый код не исполняется. Реальный служебный идентификатор SDK комнаты не передаётся вкладке. Подписки фоновой страницы и отдельных вкладок учитываются совместно, чтобы закрытие одной страницы не прекращало обновления другой. При обновлении зависимости SDK нужно повторно проверить этот адаптер.

## Стенд

`tests/detached-room.html` — изолированная имитация комнаты с настоящим клиентским SDK и отдельной вкладкой. Она не меняет настоящую комнату, не создаёт облачные аккаунты и не отправляет пользовательские заметки.
